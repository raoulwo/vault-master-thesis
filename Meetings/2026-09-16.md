### Master Thesis Idea

- Define middleware/proxy between client and server that orchestrates the migration
	- Define a protocol for communication between nodes
	- Transparent middleware for both clients and satellite servers
	- Decoupled from actual migration mechanism (agnostic)
	- Can support multiple network protocols (agnostic or at least independent)
- Define interfaces for runtimes, define design patterns
- Motivation
	- Latency spikes during replay, use middleware to mitigate the latency spikes
	- Other ideas
		- Middleware for non-abrupt handoff but canary deployment
		- Middleware for fallback mechanisms if a node doesn't process
		- Middleware forwarding to multiple servers for shadowing traffic to warm up
- Multiple migration strategies for scalability
	- 1-to-1 (or gossip / peer-to-peer)
	- 1-to-n (fan-out) -> redundancy live migration
